H One FoodBiz — POS wireframe

Low-fidelity layout for the cashier screen, M0. Fictional outlet Dapur Senja · Jakarta, terminal T1. Numbers match the database tests: 2 × Nasi Ayam + 1 × Es Teh, PB1 10%, total Rp60.500. Red circles count taps for a 3-item cash sale. The PRD target is ≤ 6 taps.

1 · Kasir, tablet landscape (main layout)

The catalog fills two-thirds of the screen and the cart stays visible. One tap on a tile adds 1 item. Tapping again adds +1 (the badge shows the qty). The status bar always shows sync status and the active shift.

DecisionWhy
Tile = +1, no qty dialogThe most common orders are 1–2 portions. A dialog would add a tap to every item.
Variant sheet only when the product has variants/modifiersMost warung menu items have none, so they stay 1 tap.
Cash chips pre-calculated (exact, nearest denominations)Saves typing the amount on most cash sales.
Default order type set per outlet (Bungkus / Makan di sini)The cashier rarely needs to change it.
Sync status always in the barThe cashier should know before closing a shift whether anything is still queued.
Out-of-stock tiles are dimmed but still tappableStock can be wrong. Blocking a sale is worse than a negative balance (see ERD).
